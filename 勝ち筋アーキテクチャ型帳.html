📖 7つの型

型1

📄読解・照合型

書類を読んで赤ペンを返す

🚪 データの入口

ユーザーがその場で上げるPDF・写真・図面＋事前に置いておくルール集（規程・法令・チェック表）

🧠 AIの使いどころ

①書類から項目を抽出 ②ルールと突き合わせて不足・違反を判定 ③次にやることを起案

🖥️ 画面

2画面：アップロード → 指摘リスト（根拠つき）。任意で管理者向け一覧

⏱️ デモで見せる30秒

実物の書類をドラッグ → 指摘が根拠つきで並ぶ → 「人がやると◯日かかる作業です」

💀 落とし穴（この型が死ぬ瞬間）

  • デモ用の書類が用意できない（機密・個人情報）
  • 1件の処理が長く壇上で待つ（CrossBeamは1タスク10〜30分）
  • 根拠が出ず“それっぽい要約”に見える
  • ルール集づくりの時間を見積もっていない

🔁 技術の置き換え例

AI：画像も読めるLLM ／ ルール：Markdownの規程集・検索索引 ／ 画面：Web・Power Apps ／ 保存：ファイル置き場

🏆 実例

  • CrossBeam Built with Opus 4.6 Claude Code Hackathon ／ 1位1週間 図面と自治体の是正通知 → 不足署名・法令違反を抽出 → 対応プランと返信案
  • Wrench Board Built with Opus 4.7 Claude Code Hackathon ／ 2位5日 回路図・基板画像・症状 → 測定ポイントと故障診断
  • MaestrIA Built with Opus 4.7 Claude Code Hackathon ／ Keep Thinking賞5日 住宅の損傷写真と説明 → 診断・重症度・見積 → 近くの職人を提案
型2

📡ライブ監視型

流れるデータを見張って異常だけ知らせる

🚪 データの入口

途切れず流れてくる映像・音声・センサー値・ログ・イベント。デモ用に録画を再生できるソースを必ず持つ

🧠 AIの使いどころ

数秒ごとの断片を構造化 → 「いつもと違う／ルールに該当」を判定 → 通知するか・何と伝えるかを決める

🖥️ 画面

1〜2画面：ライブダッシュボード＋アラート。任意で監視ルールの設定画面

⏱️ デモで見せる30秒

平常の映像 → 異常を起こす → 数秒で画面が赤くなり電話や通知が鳴る

💀 落とし穴（この型が死ぬ瞬間）

  • 会場Wi-Fiでストリームが途切れる
  • 判定の遅延が長くデモが間延びする
  • 誤検知が連発して信用を失う
  • ライブ入力に頼り本番で再現できない

🔁 技術の置き換え例

入口：カメラ・マイク・Webhook・CIイベント ／ AI：音声認識＋LLM・物体検出 ／ 保存：時系列の表 ／ 出口：Teams通知・メール・電話API

🏆 実例

  • MayDay UC Berkeley AI Hackathon 2025 ／ Fetch.ai賞・マルチモーダル賞2日間 管制無線を5秒ごとに文字起こし → 異常検知 → レーダー風画面と電話通知
  • Cameron UC Berkeley AI Hackathon 2025 ／ Grand Prize（Creativity）・Best LLM Agent2日間 監視ルールを話し言葉で指定 → 映像を解析 → メール・電話・通知
  • DocSync GitLab AI Hackathon 2026 ／ Anthropic部門 Runner Upオンライン コード変更のマージを合図に古いドキュメントを検知 → 確信度で修正MRか課題起票
  • ARIA Built with Opus 4.7 Claude Code Hackathon ／ Managed Agents賞5日 機械マニュアルPDF＋稼働信号 → 故障予測 → 作業指示書
型3

🤖代理実行型

ゴールを渡すとAIが外で手を動かす

🚪 データの入口

ユーザーの一言のゴール＋AIが働きかける外部の相手（電話・Webサイト・PC画面・業務SaaSのAPI）

🧠 AIの使いどころ

手順と相手リストを計画 → 相手とのやり取り（交渉・入力・クリック）を任せる → 結果を集約・比較

🖥️ 画面

2画面：依頼入力 → 実行の実況ログと結果比較

⏱️ デモで見せる30秒

依頼を入れる → AIが本当に電話・ブラウザ・PCを操作する様子を実況 → 結果表が出る

💀 落とし穴（この型が死ぬ瞬間）

  • 相手側に止められる（電話の自動音声・CAPTCHA・ログイン）
  • クリック精度が出ない（FaceTimeOSはキーボード操作に置き換えて回避）
  • 本物の相手に迷惑をかける・倫理の線引き
  • 実行が長く持ち時間に収まらない

🔁 技術の置き換え例

実行手段：ブラウザ操作エージェント・PC操作・電話API・RPA（PAD等）・SaaS API ／ 画面：チャット・Teams ／ 保存：実行ログ

🏆 実例

  • FaceTimeOS Cal Hacks 12.0 ／ 1st Place Grand Prize36時間 FaceTimeで自分のMacに電話 → 声で指示 → AIがPCを操作
  • Dealwise ElevenLabs × a16z Worldwide Hackathon（SF会場） ／ 会場入賞2日間 業種と郵便番号 → ブラウザAIで業者を探す → 音声AIが電話で値切る → 見積比較
  • WorkWizee Microsoft AI Agents Hackathon 2025 ／ Best Copilot Agent3週間 Teamsの一言 → Jira・ServiceNow・Confluenceを操作してインシデント対応
型4

🏭変換量産型

素材1つから完成品を並べる

🚪 データの入口

素材1つ（動画・教材テキスト・PDF・車載映像）＋出し分け条件（ターゲット属性の表・テンプレート）

🧠 AIの使いどころ

素材を分解（シーン・要点） → 構成を計画 → パーツを生成 → レビュー役AIが制約チェックして差し戻す

🖥️ 画面

2〜3画面：アップロード → 進捗 → 成果物ギャラリー

⏱️ デモで見せる30秒

素材を1つ入れる → 成果物がズラッと並ぶ（本番は事前生成分を見せ、ライブは短縮版）

💀 落とし穴（この型が死ぬ瞬間）

  • 生成が遅く壇上で待つ（動画・音声は数分単位）
  • 品質がばらつく → 計画役とレビュー役のループで抑える（ADaptは最大3周）
  • エージェント間の受け渡しが崩れる → JSON形式を固定（EduAgent）

🔁 技術の置き換え例

生成：LLM・画像／音声／動画生成API・描画ライブラリ ／ 加工：FFmpeg等 ／ 保存：ファイル置き場 ／ 画面：ギャラリー1枚

🏆 実例

  • ADapt TreeHacks 2026 ／ RunPod賞36時間 動画1本＋ターゲット属性CSV → シーン分解 → 出し分け広告を量産
  • EduAgent UC Berkeley AI Hackathon 2025 ／ Best Use of Claude 42日間 教材テキスト → 6役のエージェントで台本・アニメ・ナレーション → 解説動画
  • SUDO JPHACKS 2025 ／ 審査員特別賞Hack Day 2日間 講師の数式・説明順 → 数式アニメーション動画を自動生成
  • TARA Built with Opus 4.6 Claude Code Hackathon ／ Keep Thinking賞1週間 ドラレコ映像 → 路面状態を分析 → 投資評価PDFを1クリック
型5

🧠組織の記憶型

散らばった履歴に根拠つきで答える

🚪 データの入口

すでにある組織の履歴（コード・レビューの議論・Wiki・議事録・作業の録画）を一括で取り込む

🧠 AIの使いどころ

決定事項・ルールを抽出して台帳化 → 質問に検索＋出典つき回答 → 新しい変更と過去の決定の矛盾を指摘

🖥️ 画面

2画面：出典つき回答（既存ツールの中に出すと強い）＋知識マップ・台帳

⏱️ デモで見せる30秒

「なぜこの設計にした？」 → 過去の議論リンクつきで答える → 新しい変更に「過去の決定と矛盾」と警告

💀 落とし穴（この型が死ぬ瞬間）

  • ただの社内検索チャットに見える
  • 取り込むデータが少なく賢さが伝わらない
  • 取り込み・索引づくりに時間を溶かす
  • 出典リンクが出ず信用されない

🔁 技術の置き換え例

取り込み：Git・SharePoint・Wiki・議事録 ／ 保存：表・ベクトル索引・グラフDB ／ 画面：チャット・Teams・レビューコメント ／ AI：LLM＋検索

🏆 実例

  • LORE GitLab AI Hackathon 2026 ／ Grand Prizeオンライン レビューの議論から決定事項を台帳化 → 新しい変更で過去の決定との矛盾を指摘
  • GraphDev GitLab AI Hackathon 2026 ／ Anthropic部門 Grand Prizeオンライン コードの依存関係と変更の波及を可視化
  • Konveyor Microsoft AI Agents Hackathon 2025 ／ Best Python Agent3週間 社内ドキュメント・コード・Wiki → 出典つきQ&Aでオンボーディング
  • Show Me How ElevenLabs × a16z Worldwide Hackathon ／ 協賛賞（Shure）2日間 熟練者の作業を1回録画 → AIが手順化して多人数をガイド
型6

🎭相手役型

AIが相手を演じ人が練習し採点が返る

🚪 データの入口

シナリオの元（ガイドライン・オープンデータ・事例）＋人の行動（発話・選択・位置）

🧠 AIの使いどころ

状況と相手役を生成して演じる → 人の行動を基準で採点 → 答えを教えず問い返す

🖥️ 画面

3画面：お題 → 実践 → 振り返り（スコア・改善点）

⏱️ デモで見せる30秒

審査員に1ターンだけ体験してもらう → その場で採点とフィードバックが返る

💀 落とし穴（この型が死ぬ瞬間）

  • 採点基準が曖昧で“AIの感想”になる → 評価軸を先に作る（MaestrIAの教訓「Eval first」）
  • 1プレイが長くデモで回らない
  • 数ターンで相手役のキャラが崩れる

🔁 技術の置き換え例

対話：音声会話API・チャット ／ 基準：Markdownの評価ルーブリック ／ 画面：Web・スマホ ／ 保存：プレイ履歴の表

🏆 実例

  • Maieutic Built with Opus 4.7 Claude Code Hackathon ／ 3位5日 学生が仕様を書く → AIは答えでなく問い返す → 仕様とコードのズレを分類
  • HiNan! JPHACKS 2025 ／ ソフトバンク賞Hack Day 2日間 避難所オープンデータ＋位置 → 毎日の災害シナリオ → 実際に歩いて訓練 → バッジ
  • Pep Physical Therapy Agent ElevenLabs Worldwide Hackathon ／ オンライン部門2位2日間 声と映像でリハビリ運動のフォームをライブ指導

🚪 データの入口

身体を使った入力（手描きの絵・笑顔の写真・Webカメラの動き・鍵盤・声）

🧠 AIの使いどころ

入力の意味を読む（形・表情・コード進行） → その場で生成して返す（コース・キャラ・伴奏・小道具）

💀 落とし穴（この型が死ぬ瞬間）

  • 反応の遅延で体験が冷める（Conductrは生成部をWebAssembly化し約15ms）
  • 会場の照明・騒音で認識に失敗する
  • 課題の実在性を採点する大会では体験のあとに「誰の何の課題か」の説明が要る

🔁 技術の置き換え例

入力：カメラ・マイク・手書きキャンバス・MIDI ／ 解釈：画像認識・LLM・古典アルゴリズム ／ 生成：画像・音・3D ／ 画面：Web1枚

🏆 実例

  • AshiArt JPHACKS 2025 ／ Best Hack Award・Best Audience AwardHack Day 2日間 一筆書きの絵 → 道路網上でその形を再現したランニングコースを生成
  • Conductr Built with Opus 4.6 Claude Code Hackathon ／ Creative Exploration賞1週間 MIDI鍵盤のコード入力 → ドラム・ベース・メロディをリアルタイム生成
  • Virtual Puppet Theater Built with Opus 4.7 Claude Code Hackathon ／ Most Creative賞5日 Webカメラと声で人形を操る → AIの相方人形が会話し小道具を生成
  • スマイルグリッド 全日本AIハッカソン2025 決勝 ／ 決勝進出5時間 笑顔を撮影 → AIがキャラクター化 → 3×3の図鑑に集める

💡 読み方の注意

  • 期間の差：Opus 4.6／4.7大会（5日〜1週間）やMicrosoft大会（3週間）の実例はエージェント数・画面数が多め。48時間ではAI処理を1〜2段に絞って同じ型を組む
  • 構成図は抽象化したもの：各実例の実装をそのまま写したものではなく、共通する骨格を描いている
  • アイデアの良し悪しは扱っていない：ここにあるのは「完成して評価された構成」の型だけ
