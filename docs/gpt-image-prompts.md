# 記事用の図 — GPTに渡すプロンプト

## 使い方

- 下の「共通ルール」と、作りたい図のプロンプトを1つだけ、まとめてコピーして渡す
- 1回に作る図は1枚だけにする（まとめて頼むと情報が増えやすいため）
- 出てきた図に文字が多すぎたら「ラベルを半分に減らして」と返す

---

## 共通ルール（毎回いっしょに貼る）

```
Qiita記事に載せる図を1枚だけ作ってください。
参照してよい資料は manabi-no-wa リポジトリの README.md と DESIGN.md です。

【いちばん大事なこと】
- 一目で構成が分かることを最優先にしてください。情報量はできるだけ削ってください
- 箱（ノード）は最大7個までにしてください
- ラベルは1つあたり日本語で12文字以内にしてください。説明文や注釈は書かないでください
- 矢印の上のラベルは必要なものだけ、6文字以内にしてください
- 下に書いた要素以外は描き足さないでください。凡例・脚注・タイトル以外の見出しも不要です

【見た目】
- 横長 16:9、背景は白
- 配色は和風の落ち着いた3色だけ：生成り #F6E7D5（主役の箱）、枠線 #B36A24、若竹 #DEEBE7（人の承認）と枠線 #37776A。文字は濃い灰色 #333333
- 角丸の四角、細めの線。影・グラデーション・3D・写真風の表現は使わない
- 絵文字アイコンは各箱に1つまで
- フォントは日本語のゴシック体。文字が崩れないようにしてください
- 出力はPNG（可能ならSVGも）
```

## 図1：まなびのわの輪

差し込む場所：「話してつながる『まなびのわ』」の冒頭

```
【描くもの】
4つの箱を円形に並べ、時計回りの矢印でつないで輪にしてください。中央に「まなびのわ」と大きく1つだけ書いてください。

箱（この4つだけ）：
1. 🎙️ 集まる（ライブ）
2. 📝 残る（知見カード）
3. 🏷️ 知る（タグ）
4. 🎪 つながる（AIが場を立てる）

4から1に戻る矢印にだけ「また集まる」とラベルを付けてください。
それ以外の矢印にラベルは不要です。
```

## 図2：3体のエージェントと人の承認

差し込む場所：「ひとをつなげる『エージェント』」の冒頭

```
【描くもの】
左から右へ流れる図にしてください。元になる流れ（Mermaid）はこれです。これ以上の要素は足さないでください。

flowchart LR
  L["🎙️ まなびのライブ"] -- 終わると --> A["🎙️ A タグ付け"]
  A -- カードとタグ --> T["🏷️ タグ"]
  A -- 格上げ提案 --> G2{{管理者が承認}}
  G2 --> T
  T -- 溜まると --> B["🎪 B 場づくり"]
  B -- 打診 --> G1{{本人の同意}}
  G1 -- はい --> B
  B -- 予約 --> L
  C["🔍 C 自己分析"] -- 本人にだけ --> T

【強調】
- B（場づくり）の箱だけ少し大きくし、枠線を太くしてください（主役なので）
- 「管理者が承認」「本人の同意」の2つは若竹色 #DEEBE7 の六角形にして、人が入る場所だと分かるようにしてください
- A・B・Cの箱の右下に小さく「通知できない」「通知できる」「通知できない」とだけ添えてください（これ以外の注釈は不要）
```

## 図3：打診から予約までの流れ

差し込む場所：「④ 自律性」の「人の操作は『引き受ける』の1回だけ」

```
【描くもの】
左から右へ一直線に並ぶ7つの箱と、それをつなぐ矢印だけの図にしてください。

箱（この順番で7つだけ）：
1. 判断（open）
2. 打診
3. 👤 引き受ける
4. 予定を見る
5. 日程を決める
6. ライブを予約
7. 最初の一言

【強調】
- 3「引き受ける」だけ若竹色 #DEEBE7 にして、人が操作するのはここだけだと分かるようにしてください
- それ以外の6つは生成り色 #F6E7D5 にしてください
- 図の下に1行だけ「人の操作は1回。残りはエージェントBが実行」と書いてください
```

## 図4：全体のアーキテクチャ

差し込む場所：「OrcaRouterの使い方」の冒頭

```
【描くもの】
3つの層を左から右に並べたアーキテクチャ図にしてください。

左の層「アプリ」
- 🖥️ 画面（Next.js）

中央の層「エージェント」（縦に3つ並べる）
- 🎙️ A タグ付け
- 🎪 B 場づくり
- 🔍 C 自己分析

右の層「外部サービス」
- 🗄️ Supabase（DB・認証・RLS）
- 🐋 OrcaRouter

【つなぎ方】
- 画面 → A・B・C（起動）
- A・B・C → Supabase（読み書き）
- A・B・C → OrcaRouter（推論）
- OrcaRouterの箱の中に小さく3行だけ：「Named Router ×3」「キー ×3（上限つき）」「PIIガードレール」

【注意】
- モデル名・テーブル名・ファイル名は書かないでください
- OrcaRouterの先にある各社のモデルは描かないでください
```

## 記事に差し込むスクリーンショット（自分で撮るもの）

| 記事の場所 | 撮る画面 | 撮るときの注意 |
|---|---|---|
| まなびのライブ | ライブ画面（話している人とコメントが見える状態） | 架空社員でログインする |
| Bの説明の下 | 管理者画面の「ライブのタネ」一覧 | 段階がばらけている状態 |
| Cの説明の下 | 自己分析の結果とプロフィールの公開／非公開 | 自分のPCのデスクトップやブックマークを写さない |
| ②の1 | OrcaRouterのRequest Logs | **APIキーの値を写さない** |
| ④の介在点 | AIからの打診の画面 | 打診を受けている架空社員でログインする |
| ⑤の工夫 | 知識地図 | 画面に収まっている状態 |

※ リポジトリの `docs/evidence/05-orca-requests.png`（Request Logs）と `03-orca-keys-capped.png`（キー3本の上限）はそのまま使えます
