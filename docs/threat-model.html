🛡️ 何が危なくて どう守ったか

Day1〜Day2で出した危険を 全部1枚にした。そのまま記事の①③の材料になる。

🎯 守りの考え方は3つだけ。
① 口を持つのは幹事だけ（権限の分離）　② 入口は辞書で縛る（自由文を書かせない）　③ 止まれるようにする（上限はコードで持つ）
あとは全部この3つの応用になっている。

🗺️ エージェント設計図

3体ともトリガーが違う。口を持っているのは 🎪B だけ。

🔑
A は他人に何も言えない。通知を送る権限は B のキーにしか渡していないので、A が乗っ取られても外に出ていくものがない。──これが「機能の分離」ではなく 「権限の分離」

🗃️ テーブル設計図

データも輪になっている。ライブ → 知見カード → 人のタグ → 企て → またライブ。

かたまりテーブル守りの要
👤 人users ／ user_tagsusers に update ポリシーを作らない／visibility
🏷️ 知識tags ／ knowledge_cardsカードの tag_id が tags を参照＝辞書外は入らない
🎙️ 場lives ／ live_participants ／ messagessource_ref UNIQUE／終了後は参加できない
🎪 自律quests ／ quest_steps ／ invitationsタグごとに進行中は1つまで／ブラウザから見えない
📅 予定calendar_events本人だけ。タイトルも参加者も持たない
🧾 記録agent_runs②のレシートと ③の再開。ブラウザから見えない

🚨 踏むと終わる10個

実装で特に気をつけるところ。DESIGN.md の §8 と同じ内容。

01
一般社員が 自分を管理者にできる
✅ users に update ポリシーを作らない。update ポリシーは「どの行を」しか縛れず「どの列を」は縛れないため
02
LLM が返した宛先を そのまま使う
✅ 候補リストをコードで作り LLM の答えを照合する。自由にIDを書かせず 選ばせるだけにする
03
エージェントのAPIを誰でも叩ける
✅ CRON_SECRET で縛る。予算上限は被害の天井であって 入口の鍵ではない
04
service_role がブラウザに出る
✅ import 'server-only' を1行目に。クライアントから読まれたらビルドが落ちる
05
AIが自分の発言から知見を作る
✅ A は is_agent = false だけ読む。放っておくとタグが自己増殖する
06
知見カードに発言がそのまま載る
✅ 本文は必ず要約。逐語だと「元発言は参加者だけ」が形だけになる
07
あとから招待して過去ログを読む
✅ 終了したライブには誰も参加できない。画面のボタンではなく DB が断る
08
承認待ちで 場がひとつも立たなくなる
✅ 企てはタグの状態を条件にしない。user_tags の重なりだけで判断する
09
ループが止まらず課金され続ける
✅ 停止条件はコードで持つ。14日／候補3人／コスト上限。LLMに任せない
10
カレンダーから予定の中身が漏れる
✅ free/busy だけ取る。タイトルも参加者も最初から取りに行かない

👥 エージェント別 — 壊れ方が違う

🎙️ A 記録係
🔧 壊れ方：入力の汚染
🛡️ 守り：入口の検査
  • 会議で喋った命令文が入力になる
  • 顧客名・案件名がカードに乗る
  • 文字起こしの誤変換
  • 話者の取り違え
  • 同じ会を2回取り込む
  • 自己申告でタグが育つ
🎪 B 幹事
🔧 壊れ方：判断の暴走
🛡️ 守り：出口と上限
  • 同じ部屋が毎日立つ
  • 打診スパム・嫌がらせに使われる
  • 返事が来ず企てが止まる
  • 部分失敗で人が置き去り
  • ループが止まらない
  • 詳しい人に偏る
🔍 C 自己分析係
🔧 壊れ方：見すぎる
🛡️ 守り：持たない・止まる
  • うっかり社外秘が写る
  • 止め忘れて一日中録られる
  • 勝手にタグが全社に出る
  • 画面にプロンプトが写り込む
  • vision は高い
🔑
壊れ方が違うから 守り方も違う。この整理そのものが記事の①の骨になる。「読むAIと 喋るAIと 見るAIでは 危険度が別物」

📋 全危険と防御策

🔨 実装で守る ／ 🗃️ DBの制約で守る ／ 📝 記事に正直に書く

#危険防御策どこで軸
🎙️ A 記録係 — 入ってくるもの
A1間接プロンプトインジェクションAgent Firewall（inbound）＋ 出力をタグ辞書に縛るので任意の文字列を書けない🔨①
A2顧客名・案件名がカードに乗るPII Shield ＋ 社内固有語の禁止リスト。既定では氏名も社名も拾わない🔨①
A3文字起こしの誤変換（知見→治験）門1｜タグ辞書 ＋ かな読みで空似を判定🔨🗃️③
A4話者の取り違えカードが集まって初めて人のタグになる。1発では動かない🔨③
A5発言内容が事実として誤りカード側に裏取りバッジ。人のタグは「正しいか」ではなく「詳しいか」で見る🔨③
A6巨大入力（134分）無料モデルで足切り → 残りだけ強いモデルへ🔨②③
A7空のライブ／1人だけ0枚を正常終了として扱う🔨③
A8同じライブを2回取り込むlives.source_ref UNIQUE🗃️③
A9自己申告でタグが育つuser_tags.answer_count（他人に答えた実績）を重みにする🔨①⑤
A10貼られたくないオプトアウト ＋ visibility🗃️⑤
A11AIの発言から知見を作るis_agent = false だけ読む🔨③
A12候補タグ経由で入口が開く新語は3つの検査（形／固有名詞／空似）を通す🔨①③
🎪 B 幹事 — 出ていくもの
B1同じ部屋が毎日立つタグごとに進行中の企ては1つまで（部分ユニーク）🗃️③④
B2打診スパム・嫌がらせ1人あたりの打診上限 ＋ 送信も Firewall（egress）🔨①
B3部分失敗で人が置き去りquests.status ＋ agent_runs.status で続きから再開🗃️③
B4返事が来ず止まるnext_action_at → リマインド → 打ち切り → 別の人を探し直す🔨③④
B5ループが止まらない停止条件3つ（14日／3人／コスト上限）をコードで持つ🔨②③
B6巡回コストが毎日積む安い判定で足切り → 通ったものだけ強いモデル🔨②
B7判断が毎回ゼロからquests.outcome を次の判断材料に🗃️④
B8暴走の被害に天井がないスコープ付きAPIキー（予算・期限）🔨①②
B9詳しい人に偏るload.check を判断材料に。連続指名を避ける🔨⑤
B10コールドスタート最初だけ手で種を蒔く（source='manual'）🔨⑤
B11LLM の出した宛先をそのまま使う候補リストと照合してから使う🔨①
B12承認待ちで場が立たなくなる企てはタグの状態を条件にしない🔨④
B13カレンダーの中身が漏れるfree/busy だけ取る。タイトルも参加者も読まない🔨🗃️①
B14同じ会が短期間に再開催される14日のハードリミット＋ 判断は3値（open / wait / skip）🔨④⑤
🔍 C 自己分析係 — 見るもの
C1うっかり社外秘が写る画像を保存しない。DBに画像の列を作らない🗃️①
C2止め忘れ開始時に終了時刻を宣言し 自分で止まる🔨①③
C3勝手にタグが全社に出る本人にだけ見せる。採用を押して初めて公開の土俵へ🔨①⑤
C4画面にプロンプトが写り込むA と同じ。出力をタグ辞書に縛る🔨①
C5vision は高い差分の少ないフレームを捨てる ＋ 縮小 ＋ 終了時に1回だけ🔨②
🗃️ DB とアプリ
D1自分を管理者に昇格できるusers に update ポリシーを作らない🗃️①
D2service_role がブラウザに出るimport 'server-only'🔨①
D3エージェントAPIが公開されているCRON_SECRET で401🔨①②
D4RLS の有効化もれ全テーブル。DDLと同じ回で書く🗃️①
D5なりすまし投稿user_id default auth.uid() ＋ with check🗃️①
D6あとから招待して過去ログを読む終了したライブには参加できない（insert ポリシー）🗃️①
D7カードからトーク履歴に飛べる件数は見せる。中身は messages の RLS が弾く🗃️①
D8カードに発言が逐語で載る本文は必ず要約🔨①
D9管理者判定を画面だけでやるUIは見た目。認可は RLS とサーバーの両方🔨🗃️①
D10他人の空き時間が見えるcalendar_events は本人だけ🗃️①
D11エラーに内部情報が出る画面には短い文だけ。テーブル名を出さない🔨①
D12.env と evidence の衛生対応済み。スクショは貼る前に目視🔨①

📝 やらないと決めて 正直に書く

穴の位置を正確に言えるほうが評価される

  • マルチテナント分離：今回は1社前提。複数社に出すなら全テーブルに org_id を足して RLS の条件に入れる
  • キーの完全分離：A と B のキーは分けたが同じプロセスにある。防いでいるのは事故であって攻撃ではない
  • カレンダー実連携：デモはダミー。本番は Outlook の FreeBusy を叩く
  • リアルタイムの「現在の話題」：コストと、雑談が部屋の外に漏れる懸念のため見送り
