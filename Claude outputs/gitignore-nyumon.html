🚧 .gitignore ってなに

🎯 「このファイルは Git に持っていかないで」と書いておくメモ書き。
リポジトリの一番上に置いてあるただのテキストファイルで、ファイル名やフォルダ名を1行ずつ並べるだけ。そこに書いたものは git add しても入らない。

🏠 たとえるなら 引っ越しのときに玄関に貼る「これは持っていかない」の紙。段ボールに詰める人（Git）が玄関で毎回それを見て、書いてあるものは詰めずに家に置いていく。

🗺️ ファイルが GitHub に届くまで

Git ではファイルが3つの場所を通って GitHub に着く。.gitignore は一番最初の門にいる。

💻
作業フォルダ
いま手元にあるファイル全部。PC の中
🚧 .gitignore
➜
git add
📦
ステージ
次の記録に入れるものを並べる台
➜
git commit
📚
履歴
PCの中に残る記録。ここに入ると消しにくい
➜
git push
🌍
GitHub
public にした瞬間 全世界が読める
🚧 .gitignore に書いたファイルは、最初の門で止まる。だから git add .（今あるもの全部を詰めて）と打っても入らない。「全部」と言っても玄関の紙に書いてあるものは詰まれない。

⚠️ いちばん大事な性質

一度コミットしたファイルは あとから .gitignore に書いても消えない

.gitignore が効くのはまだ門を通っていないファイルだけ。一度 📚履歴 に入ったものは、あとで削除しても「あの日こういう中身だった」という記録が履歴に残り続ける。public にすれば誰でも遡って読める。

🔑 だから合言葉は 「入れてから消す」ではなく「最初から入れない」。

これが、トランスクリプトを B（最初から入れない）で行きたい理由です。いまはまだ一度もコミットされていないので、今なら1行足すだけで終わる。

✍️ やるとしたらこれだけ

AIhack フォルダの .gitignore の末尾に足す3行。

# 議事録（実名の会話が入っている。publicリポジトリには出さない）
docs/transcripts/*
!docs/transcripts/.gitkeep
行意味
docs/transcripts/*このフォルダの中身を全部持っていかない
!docs/transcripts/.gitkeep! は例外の印。これだけは持っていく。
Git は空のフォルダを記録できないので、.gitkeep という空ファイルを1個だけ残してフォルダの存在だけを伝える
🤝
ファイルは PC の中にはそのまま残る。消えるわけではないので、Cowork からは今までどおり読める。変わるのは「GitHub に行かなくなる」ことだけ
